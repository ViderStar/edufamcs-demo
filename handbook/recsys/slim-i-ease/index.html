Линейные item-item модели: SLIM и EASE

17 мин АЛАртем Лебедевич 10 ноября 2026

Классический item-based kNN считает сходство двух объектов по формуле, которую выбрал человек: косинус, Жаккар, условная вероятность. Формула не знает, для чего её будут использовать. Если пользователь купил объекты a и a' — почти дубли друг друга, — и оба похожи на c, kNN засчитает свидетельство в пользу c дважды, хотя a' ничего не добавляет к a. Идея линейных моделей — заменить эвристику обучаемой матрицей W \in \mathbb{R}^{|I| \times |I|} и подобрать её так, чтобы по истории пользователя восстанавливалась его же история.

Постановка: автоэнкодер без скрытого слоя

Пусть X \in \{0,1\}^{|U| \times |I|} — матрица взаимодействий (строка — пользователь). Модель предсказывает скоры как

\hat X = X W, \qquad \hat x_{ui} = \sum_{j} x_{uj} W_{ji}.

Скор объекта i для пользователя — сумма весов от объектов, с которыми он уже взаимодействовал. Это автоэнкодер, у которого нет ни скрытого слоя, ни нелинейности: вход и выход имеют размерность |I|, а вся модель — одна матрица. Каждый столбец W_{\cdot i} — отдельная линейная регрессия «предскажи столбец i по остальным столбцам». Если не добавить ограничений, оптимум тривиален: W = I даёт \hat X = X с нулевой ошибкой, и модель ничего не рекомендует. Поэтому два семейства моделей отличаются тем, как они запрещают тождественное решение и регуляризуют W.

SLIM (2011)

Ning и Karypis (ICDM 2011) назвали подход Sparse LInear Methods. Задача для всей матрицы:

\min_{W} \; \tfrac12 \|X - XW\|_F^2 + \tfrac{\beta}{2}\|W\|_F^2 + \lambda \|W\|_1 \quad \text{при } W \ge 0,\ \mathrm{diag}(W) = 0.
  • \mathrm{diag}(W)=0 — запрет тождественного решения: объект нельзя предсказывать самим собой.
  • W \ge 0 — только положительные связи («купили j — больше шансов на i»). Интерпретируемо и устойчиво.
  • \ell_1 даёт разреженные столбцы: у каждого объекта остаётся десяток-другой соседей, как у kNN, но выбранных оптимизацией, а не пороговым отсечением.
  • \ell_2 вместе с \ell_1 — elastic net, стабилизирует решение при коррелированных столбцах.

Столбцы W не связаны друг с другом, поэтому задача распадается на |I| независимых elastic-net регрессий, и их решают координатным спуском параллельно. Это сразу и сила, и слабость: на каталоге в сотни тысяч объектов нужно сотни тысяч регрессий, и обучение занимает часы или сутки. SLIM стал сильным бейзлайном на MovieLens и Netflix, но широко применялся ограниченно именно из-за цены обучения. Для ускорения на практике ограничивают список кандидатов-соседей в каждой регрессии (предотбор через kNN).

EASE (2019)

Harald Steck (WWW 2019, Embarrassingly Shallow Autoencoders for Sparse Data) задал вопрос: что будет, если выбросить \ell_1 и неотрицательность и оставить только \ell_2? Тогда задача становится гладкой и квадратичной, а её решение — в замкнутой форме.

\min_{B} \; \|X - XB\|_F^2 + \lambda \|B\|_F^2 \quad \text{при } \mathrm{diag}(B) = 0.

Вывод

Без ограничения на диагональ решение — гребневая регрессия: \hat B = (X^\top X + \lambda I)^{-1} X^\top X. Добавим ограничение \mathrm{diag}(B)=0 множителями Лагранжа \gamma \in \mathbb{R}^{|I|}:

\mathcal{L}(B,\gamma) = \|X - XB\|_F^2 + \lambda\|B\|_F^2 + 2\gamma^\top \mathrm{diag}(B).

Обозначим G = X^\top X (матрица Грама, |I|\times|I|) и \hat P = (G + \lambda I)^{-1}. Приравнивая градиент по B нулю:

-2G + 2(G + \lambda I)B + 2\,\mathrm{diagMat}(\gamma) = 0 \;\Rightarrow\; B = \hat P\,\big(G - \mathrm{diagMat}(\gamma)\big) = I - \hat P\,\big(\lambda I + \mathrm{diagMat}(\gamma)\big).

Условие \mathrm{diag}(B)=0 даёт 1 - \hat P_{jj}(\lambda + \gamma_j) = 0, то есть \lambda + \gamma_j = 1/\hat P_{jj}. Подставляя,

\boxed{\,B_{ij} = -\frac{\hat P_{ij}}{\hat P_{jj}} \ (i \ne j), \qquad B_{ii} = 0, \qquad \hat P = (X^\top X + \lambda I)^{-1}\,}

Это весь алгоритм обучения: собрать матрицу Грама, обратить, нормировать столбцы на диагональ и обнулить диагональ.

python
import numpy as np
import scipy.sparse as sp

def fit_ease(X: sp.csr_matrix, lam: float = 500.0) -> np.ndarray:
    G = (X.T @ X).toarray().astype(np.float64)
    G[np.diag_indices_from(G)] += lam
    P = np.linalg.inv(G)
    B = -P / np.diag(P)          # делит каждый столбец j на P_jj
    B[np.diag_indices_from(B)] = 0.0
    return B

def recommend(X_user: sp.csr_matrix, B: np.ndarray, k: int = 20) -> np.ndarray:
    scores = X_user @ B                        # [n_users, |I|]
    scores[X_user.nonzero()] = -np.inf         # маскируем уже просмотренное
    top = np.argpartition(-scores, k, axis=1)[:, :k]
    order = np.take_along_axis(scores, top, 1).argsort(1)[:, ::-1]
    return np.take_along_axis(top, order, 1)

B = -P / np.diag(P) делит столбец j на P_{jj} благодаря бродкастингу по строкам. Маскирование просмотренного обязательно: линейная модель с \mathrm{diag}(B)=0 всё равно может ставить уже виденные объекты выше новых: скор виденного j — это \sum_{k \ne j} x_{uk} B_{kj}, и он велик, если j похож на остальную историю.

Пример 3×3

Три объекта A,B,C и шесть пользователей: \{A,B\}, \{A,B\}, \{A,B,C\}, \{B,C\}, \{A,C\}, \{C\}. Каждый объект встречается у четырёх пользователей, пары AB — у трёх, AC и BC — у двух. Матрица Грама и \hat P=(G+\lambda I)^{-1} при \lambda=1:

G=\begin{pmatrix}4&3&2\\3&4&2\\2&2&4\end{pmatrix},\qquad \hat P=\frac1{64}\begin{pmatrix}21&-11&-4\\-11&21&-4\\-4&-4&16\end{pmatrix}.

Делим столбец j на \hat P_{jj}, меняем знак и обнуляем диагональ (B_{ij}=-\hat P_{ij}/\hat P_{jj}):

B=\begin{pmatrix}0&11/21&1/4\\11/21&0&1/4\\4/21&4/21&0\end{pmatrix}\approx\begin{pmatrix}0&0{,}524&0{,}250\\0{,}524&0&0{,}250\\0{,}190&0{,}190&0\end{pmatrix}.

Пользователь с одним объектом A получает скоры — первую строку: B — 0{,}524, C — 0{,}250. Пользователь с \{A,B\} получает для C сумму 0{,}25+0{,}25=0{,}5. Матрица несимметрична: вес A\to C равен 0{,}25, а C\to A — 0{,}19, потому что столбцы нормируются каждый на свой \hat P_{jj}.

Почему это работает

Матрица \hat P — регуляризованная обратная матрица Грама; с точностью до центрирования и нормировки это оценка обратной ковариации (precision matrix). Известный факт из гауссовых графических моделей: -P_{ij}/P_{jj} — коэффициент при объекте i в линейной регрессии объекта j на все остальные объекты. То есть B хранит условные зависимости, а не маргинальные корреляции. Именно это решает проблему «дважды засчитанного» сходства из начала статьи: если a' почти дублирует a, то при известном a он почти ничего не добавляет к предсказанию c, и вес делится между ними, а не суммируется. Единственный гиперпараметр — \lambda; он на порядки больше, чем в обычной гребневой регрессии, потому что X^\top X содержит счётчики совстречаемости (для крупных наборов — тысячи).

Цена и масштаб

Обращение |I|\times|I| плотной матрицы стоит O(|I|^3) по времени и O(|I|^2) по памяти. На практике потолок — порядка 50–100 тыс. объектов (при 50 тыс. и float32 матрица занимает 10 ГБ). Для типичного каталога это значит, что модель нельзя запустить «как есть» на миллионе SKU. Приёмы:

  • Отбор по популярности. Оставить N самых частых объектов (хвост всё равно слабо покрыт данными), редкие обслужить другой моделью.
  • Шардирование по смыслу. Отдельная матрица на категорию или вертикаль, если пользователи редко пересекают их.
  • Разреженные приближения. SANSA (Spišák et al., RecSys 2023) не обращает X^\top X + \lambda I, а строит разреженную приближённую обратную через разреженное (в том числе неполное) разложение Холецкого; плотная матрица не появляется ни при обучении, ни при выдаче, плотность модели задаётся заранее, и авторы масштабируют EASE до миллионов объектов.
  • Низкоранговые. ELSA (Vančura et al., RecSys 2022) ищет B = \tilde A\tilde A^\top - I, где \tilde A — матрица |I| \times r со строками единичной длины (диагональ B получается нулевой); обучается SGD на GPU, память O(|I| r).
  • Другие регуляризаторы. EDLAE (Steck, NeurIPS 2020) разбирает, как ещё отучить линейный автоэнкодер от тождественного решения. Обычный dropout на входе помогает лишь частично: он эквивалентен \ell_2-штрафу, взвешенному по популярности объекта. Dropout с «усиленным» весом ошибки на выпавших координатах (emphasized denoising) устраняет тождественное решение полностью; для полноранговой модели решение тоже замкнутое, есть и низкоранговая версия. Связь с матричным разложением разобрана в Jin et al. (KDD 2021): по замкнутым решениям видно, что регрессия вроде EASE и разложение родственны и различаются лишь тем, как «сжимают» сингулярные числа матрицы X; там же — какой диапазон \lambda разумен.

Автоэнкодеры как нелинейное продолжение

Линейная модель — частный случай автоэнкодера. Нелинейные версии добавляют узкий скрытый слой и функции активации.

  • Mult-VAE (Liang et al., WWW 2018). Вариационный автоэнкодер с мультиномиальным правдоподобием: вход — вектор взаимодействий пользователя x_u, кодировщик выдаёт \mu, \sigma, декодер — распределение по каталогу \pi(z)=\mathrm{softmax}(f_\theta(z)), лог-правдоподобие \sum_i x_{ui}\log\pi_i. Потеря — ELBO с весом \beta на KL-члене, подобранным отжигом (обычно \beta \approx 0{,}2). Мультиномиальная потеря ближе к ранжированию, чем гауссова или логистическая, потому что объекты конкурируют за ограниченную вероятностную массу.
  • RecVAE (Shenbin et al., WSDM 2020). Добавляет композитный априор, нормировку \beta на число взаимодействий пользователя и чередование шагов кодировщика и декодера; стабильно выигрывает у Mult-VAE.

Различие по сути: EASE выучивает матрицу |I|\times|I| без узкого места, а VAE сжимает пользователя в вектор размерности d \ll |I|. Узкое место помогает обобщать, когда данных много, и мешает, когда их мало: в экспериментах Steck (2019) на плотном ML-20M Mult-VAE и EASE почти вровень, а на более разреженном Million Song Dataset EASE заметно впереди.

Почему простые модели догнали нейросети

Конец 2010-х — время, когда каждая конференция приносила десяток «SOTA-нейросетей». В 2019 году Dacrema, Cremonesi и Jannach разобрали 18 нейросетевых алгоритмов с ведущих конференций; воспроизвести с разумными усилиями удалось 7. Шесть из них часто проигрывали простым эвристикам — настроенным kNN и графовым P^3_\alpha, RP^3_\beta (см. графовые модели), а седьмой обгонял эвристики, но не стабильно обгонял хорошо настроенный линейный метод (SLIM). Anelli et al. (2022) сравнили десять алгоритмов, классических и нейросетевых, с настройкой всех бейзлайнов на трёх популярных датасетах: явного победителя нет, но ни по одной метрике точности лучшей не оказалась нейросеть, а линейные модели, kNN и классическое матричное разложение стабильно в числе сильных.

Причин несколько:

  1. Настройка гиперпараметров бейзлайнов в статьях недостаточна, а у нейросетей — гораздо подробнее.
  2. Разреженные данные: у большинства пользователей десятки взаимодействий; нелинейность выигрывает у линейной модели только когда есть данные для её обучения.
  3. Протоколы оценки: случайный сплит, сэмплированные метрики, утечка из будущего (подробнее — в статье про офлайн-метрики).

Вывод для практики: любая новая модель должна сравниваться с настроенными EASE и item-kNN, иначе прирост может оказаться иллюзией. Оговорка: это относится к «статическому» top-N по матрице взаимодействий. В next-item prediction при глобальном временном сплите настроенный SASRec с полной кросс-энтропией или gBCE (2023) обычно обгоняет EASE — см. последовательные модели. EASE остаётся обязательным бейзлайном, но не потолком.

Как EASE используют в индустрии

  • Источник кандидатов. Берём строку \hat x_u = x_u B, маскируем просмотренное, оставляем топ-N (100–500). Это первая стадия двухстадийной схемы: быстрая, без признаков, но с хорошим Recall.
  • Признак ранжирующей модели. Скор EASE для пары (u,i) и ранг в списке добавляют в градиентный бустинг рядом с контекстными признаками. Рядом со скорами из двухбашенной сети они дают разные сигналы: EASE хорошо ловит условные связи, а нейросеть — признаки и свежесть.
  • Item-to-item. Строка B_{j\cdot} — это скоры для «пользователя», у которого в истории один объект j (e_j^\top B), то есть готовый список «с этим покупают» для карточки товара. В отличие от kNN, веса уже очищены от сходства, которое объясняется через третьи объекты.
  • Веса событий. Бинарная матрица X — лишь один вариант. Можно положить в X веса w_{ui}: покупка = 3, добавление в корзину = 2, просмотр = 1 (подбираются на валидации), а также обрезать вклад повторных событий логарифмом. Для нескольких типов событий считают одну матрицу с весами либо отдельные B на каждый тип с последующим взвешиванием.
  • Затухание по времени. Старые события умножают на e^{-\Delta t/\tau}; обновление раз в сутки — пересчитать G инкрементально и заново обратить.

Подводные камни

  • Память и время обращения. Считать в float64 на CPU по 30 тыс. объектов — минуты; на 100 тыс. — уже часы и десятки гигабайт. Матрица X^\top X + \lambda I симметрична и положительно определена, поэтому быстрее и устойчивее обращать её через разложение Холецкого (torch.linalg.cholesky + torch.linalg.cholesky_inverse на GPU, float32 обычно хватает при разумном \lambda).
  • Выбор \lambda. При слишком малом \lambda матрица плохо обусловлена, при слишком большом \hat P \approx (I - G/\lambda)/\lambda и B_{ij} \approx G_{ij}/\lambda: модель вырождается в ненормированную совстречаемость, то есть в популярное. Перебирают по логарифмической сетке (50, 200, 500, 1000, 3000) на валидации.
  • Популярность. Модель переоценивает популярные объекты; в рекомендациях «с этим покупают» их часто надо демпфировать (деление на степень популярности).
  • Холодный старт. У нового объекта нулевой столбец в X, EASE о нём ничего не знает. Нужны контентные источники.
  • Утечка. Пользователь, чьи события в X участвуют в обучении B, а затем проверяется на том же — классическая ошибка. Матрицу строят до отсечки по времени, а тестовые события используют только как цель.
  • На собеседовании: выведите замкнутое решение EASE и объясните роль ограничения \mathrm{diag}(B)=0.
  • На собеседовании: чем EASE отличается от SLIM и от item-kNN и почему обратная матрица Грама лучше сырой совстречаемости?
  • На собеседовании: что делать, если каталог — миллион объектов, и сколько стоит обучение EASE?

Проверь себя

Почему без ограничения $\mathrm{diag}(B)=0$ модель бесполезна?

Оптимум тривиален: B=I даёт \hat X=X с нулевой ошибкой, и объект предсказывается самим собой. Запрет диагонали заставляет предсказывать столбец по остальным.

Что хранит матрица $B$ и чем это лучше сходства по совстречаемости?

-\hat P_{ij}/\hat P_{jj} — коэффициент при i в регрессии j на все остальные объекты, то есть условная зависимость. Если a' дублирует a, вес делится между ними, а не засчитывается дважды, как в kNN.

Что происходит при очень большом $\lambda$?

\hat P\approx(I-G/\lambda)/\lambda и B_{ij}\approx G_{ij}/\lambda: модель вырождается в ненормированную совстречаемость, то есть в популярное. При слишком малом \lambda матрица плохо обусловлена.

Почему EASE нельзя запустить на миллионе SKU и как это обходят?

Обращение плотной матрицы |I|\times|I| стоит O(|I|^3) по времени и O(|I|^2) по памяти. Берут самые частые объекты, шардируют по категориям или используют разреженные и низкоранговые приближения (SANSA, ELSA).

Всегда ли EASE побеждает последовательные модели?

Нет. Он сильный бейзлайн для «статического» top-N, но в next-item prediction при временном сплите настроенный SASRec с полной кросс-энтропией или gBCE обычно его обгоняет. EASE остаётся обязательным бейзлайном, не потолком.
