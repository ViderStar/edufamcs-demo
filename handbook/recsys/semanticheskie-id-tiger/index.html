Семантические ID и генеративный retrieval: TIGER

17 мин АЛАртем Лебедевич 9 ноября 2026
Содержание Идея и место в историиСемантические ID: остаточная квантизацияКод: остаточная квантизация через k-means и trie допустимых префиксовTIGER: генеративный retrievalРазвитие 2023–2025Сводная таблицаТрезвый взгляд (2025–2026)Вопросы на собеседованияхЧто почитать

Классический рекомендатель (ALS, двухбашенная сеть, SASRec) устроен одинаково: у каждого объекта есть вектор в таблице эмбеддингов, а предсказание — скалярное произведение вектора пользователя с этой таблицей плюс ANN-поиск. У подхода два структурных недостатка. Таблица растёт вместе с каталогом (миллиарды видео × сотни чисел). И у нового объекта вектора нет, пока не накопится история. В 2023 году команда Google предложила другой интерфейс: не искать ближайший вектор, а генерировать идентификатор следующего объекта токен за токеном, как язык-модель генерирует слова. Условием работы стало, чтобы идентификатор был не случайным номером, а осмысленной последовательностью кодов — семантическим ID.

Для читателя, знакомого с поиском: идея родственна генеративному поиску из главы «Генеративный поиск» (там модель генерирует идентификаторы документов), только вместо запроса на входе — история действий пользователя.

Идея и место в истории

Этап Идентификатор объекта Что не решено
ALS, двухбашенные сети (2008–2019) строка таблицы эмбеддингов память растёт с каталогом, холодный старт
SASRec, BERT4Rec (2018–2019) то же, но вход — последовательность то же; выход — softmax по всему каталогу
Семантические ID, TIGER (2023) кортеж кодов (c_1,\dots,c_L) точность на популярном, коллизии

Главное изменение — выходной слой. Вместо softmax по |I|=10^6–10^9 объектов модель выдаёт L распределений по небольшому алфавиту (например, 256 кодов на уровень). Три уровня по 256 кодов адресуют 256^3 \approx 16{,}7 млн объектов, четыре — 4{,}3 млрд, а таблицы эмбеддингов кодов занимают доли мегабайта (в TIGER — 3 \times 256 векторов размерности 32, около 100 КБ во float32).

Семантические ID: остаточная квантизация

Нужно превратить вектор объекта z \in \mathbb{R}^d — контентный эмбеддинг (из текстового энкодера по названию, описанию, категории или из аудио/видео-модели) или, как в RQ-VAE ниже, его сжатое латентное представление — в короткую последовательность дискретных кодов, где похожие объекты имеют общий префикс. Для этого используют остаточную квантизацию: на каждом уровне l есть свой словарь \{e^l_k\}_{k=1}^{K}, и кодируется остаток предыдущего уровня.

r_0 = z, \qquad c_l = \arg\min_{k}\,\lVert r_{l-1} - e^{l}_k\rVert, \qquad r_l = r_{l-1} - e^{l}_{c_l}, \qquad l=1,\dots,L.

Приближение объекта — сумма выбранных векторов \hat z = \sum_l e^l_{c_l}. Первый код задаёт «крупную» категорию (комедия / документалистика), второй — подтип внутри неё, дальше — детали; отсюда порядок «от общего к частному». Сама остаточная (многоступенчатая) векторная квантизация — старая идея сжатия сигналов, известная с 1980-х и позже применявшаяся в приближённом поиске соседей. В нейросетевом виде её популяризовали аудиокодек SoundStream (Zeghidour et al., arXiv 2021) и RQ-VAE (Lee et al., CVPR 2022, генерация изображений); TIGER ссылается на обе работы. RQ-VAE — это энкодер z=\mathrm{Enc}(x), остаточный квантизатор и декодер \mathrm{Dec}(\hat z), обученные совместно с потерей

\mathcal{L}= \underbrace{\lVert x-\mathrm{Dec}(\hat z)\rVert^2}_{\text{реконструкция}} + \sum_{l=1}^{L}\Big(\lVert \mathrm{sg}[r_{l-1}]-e^l_{c_l}\rVert^2+\beta\,\lVert r_{l-1}-\mathrm{sg}[e^l_{c_l}]\rVert^2\Big),

где \mathrm{sg} — stop-gradient, а второе слагаемое — обычная для VQ-VAE потеря «подтягивания» словарей к остаткам и энкодера к словарям. Для устойчивости словари инициализируют k-means по первому батчу, иначе значительная часть кодов «умирает» (codebook collapse).

Альтернатива без обучения VAE. Иерархический (или остаточный) k-means по контентным эмбеддингам: на каждом уровне кластеризуем остатки. Это тот же алгоритм с той же формулой, но без декодера и без риска «мёртвых» кодов. В ряде сравнений он не уступает RQ-VAE, а универсально лучшей схемы, по воспроизводимым исследованиям, нет (см. раздел о трезвом взгляде ниже).

Коллизии. Два разных объекта могут получить один и тот же кортеж (c_1,\dots,c_L). В TIGER добавляется ещё один токен c_{L+1} — порядковый номер объекта среди тех, у кого код совпал: однозначность гарантирована, а лишний токен несёт ноль смысла (по сути, это случайный хвост). Слишком много коллизий — сигнал, что кодов или уровней мало.

Код: остаточная квантизация через k-means и trie допустимых префиксов

python
import numpy as np
from sklearn.cluster import KMeans

def fit_rq(Z, levels=3, k=16, seed=0):
    """Остаточная квантизация: на каждом уровне k-means по остаткам."""
    codebooks, codes, R = [], [], Z.copy()
    for _ in range(levels):
        km = KMeans(k, n_init=4, random_state=seed).fit(R)
        c = km.predict(R)
        codebooks.append(km.cluster_centers_)
        codes.append(c)
        R = R - km.cluster_centers_[c]          # r_l = r_{l-1} - e_{c_l}
    return codebooks, np.stack(codes, 1), R

def add_dedup_token(codes):
    """Коллизии: (L+1)-й токен — порядковый номер среди объектов с тем же кодом."""
    seen, out = {}, []
    for row in map(tuple, codes):
        j = seen.get(row, 0); seen[row] = j + 1
        out.append(row + (j,))
    return np.array(out)

def build_trie(sids):
    trie = {}
    for s in sids:
        node = trie
        for tok in s:
            node = node.setdefault(int(tok), {})
    return trie

def allowed_next(trie, prefix):
    """Какие токены допустимы после префикса — маска для ограниченного декодирования."""
    node = trie
    for tok in prefix:
        node = node.get(tok)
        if node is None:
            return []
    return sorted(node)

Z = np.random.default_rng(0).normal(size=(2000, 32))      # в жизни — текстовые эмбеддинги
codebooks, codes, R = fit_rq(Z)
print("доля невязки:", (R ** 2).sum() / (Z ** 2).sum())
sids = add_dedup_token(codes)
trie = build_trie(sids)
print(allowed_next(trie, [int(sids[0][0])]))

На случайных гауссовых данных остаётся около 63% дисперсии (шум плохо сжимается), а у настоящих текстовых эмбеддингов структура есть, и невязка заметно меньше. Коллизии появляются даже при запасе ячеек: 2000 объектов на трёх уровнях по 16 кодов (4096 ячеек) занимают около 1600 различных кортежей, примерно треть объектов делит ячейку с кем-то ещё, а дополнительный токен доходит до 4. Кластеры k-means неравномерны, поэтому ячеек нужно заметно больше, чем объектов.

TIGER: генеративный retrieval

TIGER (Recommender Systems with Generative Retrieval, Rajput et al., Google, NeurIPS 2023, arXiv:2305.05065) — первая работа, показавшая этот рецепт целиком.

Конвейер.

  1. Для каждого объекта берут контентный эмбеддинг (в статье — предобученный текстовый энкодер по названию, цене, бренду, категории) и квантуют его через RQ-VAE в кортеж из трёх кодов + токен против коллизий.
  2. История пользователя i_1,\dots,i_n превращается в последовательность токенов: SID первого объекта, затем второго и т. д.
  3. Seq2seq-трансформер (T5-подобный encoder–decoder) обучается по токенам SID последнего объекта i_{n+1} при условии истории — обычная кросс-энтропия, как в языковой модели.
  4. На инференсе beam search порождает несколько кортежей, которые декодируют обратно в объекты; ширина луча — число кандидатов.

Невалидные ID и ограниченное декодирование. Модель может сгенерировать последовательность кодов, которой нет ни у одного объекта («призрак»). В исходной статье TIGER маски не было: для топ-10 доля невалидных ID составила 0,1–1,6% в зависимости от датасета, и авторы предложили просто расширить луч и отфильтровать лишнее. В последующих работах стандартом стало ограниченное декодирование: на каждом шаге допустимы только токены, которые продолжают некоторый реальный префикс из словаря SID, — то есть обход trie (префиксного дерева), как в коде выше. Тогда несуществующих выдач нет вовсе, цена — небольшая надстройка над beam search.

Результаты и честная оценка. На трёх датасетах Amazon Reviews (Beauty, Sports, Toys) TIGER в статье превзошёл SASRec, BERT4Rec, S³-Rec, P5 и другие бейзлайны по Recall@5/10 и NDCG@5/10. Относительный выигрыш над лучшим бейзлайном — от +0,15% (Recall@10 на Beauty) до +29% (NDCG@5 на Beauty); по NDCG прирост заметнее, чем по Recall. Оговорки: (а) каталоги — 12–18 тыс. объектов, средняя длина истории 8–9 действий, это далеко от промышленного масштаба; (б) числа бейзлайнов взяты из более ранней работы (S³-Rec), где SASRec обучался в исходной конфигурации с бинарной кросс-энтропией и сэмплированными негативами, а SASRec с полной кросс-энтропией заметно сильнее (см. последовательные модели); (в) онлайн-A/B в статье нет.

Холодные объекты. Авторы исключили 5% тестовых объектов из обучения и показали, что TIGER может их рекомендовать — но не прямой генерацией: к кандидатам подмешивают невиданные объекты, у которых первые три кода совпали со сгенерированным SID, а гиперпараметр \varepsilon ограничивает их долю в выдаче. Сравнение шло только с kNN в том же семантическом пространстве. Более поздняя проверка в контролируемых условиях (LIGER, 2024, см. ниже) показала, что без такой подмешки TIGER почти никогда не порождает холодные объекты (Recall@10 около нуля на трёх из четырёх датасетов): модель переобучается на объекты, виденные при обучении.

Плюсы.

  • Память не растёт с каталогом: словари кодов малы; никакой огромной таблицы эмбеддингов.
  • Новый объект получает SID по контенту сразу, без накопления истории, и наследует статистику объектов с тем же префиксом. Чтобы он реально попал в выдачу, нужна явная подмешка по префиксу (см. выше): сама модель холодные объекты почти не генерирует.
  • Обмен статистикой между похожими объектами: объекты одной тематики делят префикс, и редкие объекты учатся вместе с частыми (своего рода регуляризация).
  • Единый интерфейс «последовательность → последовательность» без отдельной ANN-инфраструктуры.

Минусы.

  • В контролируемых сравнениях генеративный retrieval по общему качеству уступает плотному retrieval с выделенными эмбеддингами (LIGER): у кортежа общие префиксы с десятками других объектов, и «различить» два очень похожих хита сложнее.
  • Качество упирается в токенизацию: плохой SID необратимо теряет информацию. Дрейф каталога требует перекодирования, а любое изменение словарей ломает обученную модель.
  • Инференс — авторегрессия с beam search: L{+}1 последовательных шагов декодера и ширина луча B; задержка выше, чем у одного скалярного произведения с ANN.
  • Скрытая цена контентного энкодера: SID не может быть лучше эмбеддинга, из которого получен.

Развитие 2023–2025

  • SID в ранжировании YouTube (Singh et al., 2024, Better Generalization with Semantic IDs: A Case Study in Ranking for Recommendations, arXiv:2306.08121, RecSys 2024). Не генерация, а замена случайных хэшей ID на SID внутри обычной ранжирующей модели: она лучше обобщается на новые и редкие видео без потерь на общем качестве. Показательный пример того, что SID полезны и в классической архитектуре; префикс-n-граммы и SentencePiece-разбиение SID работают как «субслова» для объектов.
  • LC-Rec (Zheng et al., 2024, Adapting Large Language Models by Integrating Collaborative Semantics for Recommendation, arXiv:2311.09049, ICDE 2024). Словарь LLM расширяется токенами SID; модель дообучается на задачах, сопоставляющих SID с текстом и историей. Это мост к главе про LLM.
  • LIGER (Yang et al., Meta и Висконсинский университет, 2024, Unifying Generative and Dense Retrieval for Sequential Recommendation, arXiv:2411.18814). Сначала честное сравнение в одинаковых условиях: на академических датасетах плотный последовательный retrieval сильнее TIGER и по общему качеству, и особенно на холодных объектах, которые TIGER почти не порождает. Затем гибрид: генеративная часть beam search'ем выдаёт около 20 кандидатов, к ним добавляются холодные объекты, а плотная часть (сравнение выхода энкодера с текстовыми представлениями объектов) их ранжирует. Это сокращает разрыв с плотным retrieval и закрывает холодный старт; авторы подчёркивают, что выводы получены на небольших бенчмарках.
  • ActionPiece (Hou et al., Google DeepMind, ICML 2025, arXiv:2502.13581). Токенизирует не объект, а действие (набор признаков события) и объединяет часто встречающиеся совместные признаки в токены, как BPE, причём слияние зависит от соседних действий (контекстная токенизация).

Трезвый взгляд (2025–2026)

Академический энтузиазм сменился сравнениями в одинаковых условиях.

  • Масштабирование. Understanding Generative Recommendation with Semantic IDs from a Model-scaling View (Liu, Collins, Tang, Zhao, Shah, Ju, arXiv:2509.25522, принята на KDD 2026): рост энкодера, квантизатора и самой рекомендательной модели в SID-подходе быстро упирается в потолок; авторы связывают это с ограниченной ёмкостью SID. LLM, используемая напрямую как рекомендатель (диапазон моделей от 44M до 14B параметров), масштабируется лучше — до 20% выше лучшего SID-подхода по их измерениям. Вывод, что SID — промежуточное звено, а не окончательная архитектура, спорен (сравнение сделано на академических датасетах), но он объясняет интерес к LLM-рекомендателям из главы 17.
  • Что делает SID хорошим. What Makes a Good Semantic ID for Generative Recommendation? A Reproducibility Study (Chen, Fu, Zhao, Zhao, Ren, arXiv:2609.24430, SIGIR-AP 2026): эффект выбора схемы SID немонотонен, универсально лучшей нет, RQ-VAE и OPQ работают нестабильно по датасетам, сбалансированность кодов первого уровня — полезная диагностика, но не предсказатель качества, а удлинение SID или увеличение бэкбона не всегда помогает.
  • Обзоры. «A Modular Survey for Semantic ID-Based Generative Recommendation» (Hu et al., Preprints.org, май 2026, с открытым тулбоксом UniGenRec для контролируемых абляций по этапам конвейера) и «Generative Recommendation in Dynamic Catalogs: A Survey of Item Admission, Semantic ID Evolution, and Model Adaptation» (Preprints.org, сентябрь 2026: как быть с SID, когда объекты добавляются и меняются после обучения). Это препринты без рецензирования, их полезно читать как карты области, не как доказательства.

Практический вывод для небольшой команды: SID — разумный инструмент, когда нужны холодные объекты и компактная память (огромный каталог, быстро меняющийся ассортимент, ограничение на размер индекса). Если каталог — сотни тысяч объектов и данных хватает, SASRec/EASE + бустинг (глава «Двухстадийная схема») проще, быстрее и сопоставимы по точности.

Вопросы на собеседованиях

  • Зачем остаточная, а не одноуровневая квантизация? Один уровень на K^L кодов потребовал бы словарь размера K^L с непосильным k-means; остаточная схема достигает той же ёмкости суммой L\cdot K векторов, а иерархия кодов получается автоматически.
  • Как обрабатываются коллизии и что делать, если их много? Дополнительный токен; увеличить K или L; перекластеризовать с учётом баланса.
  • Почему нужно ограниченное декодирование? Иначе beam search выдаёт кортежи, не соответствующие ни одному объекту. Маска по trie исключает это.
  • Чем TIGER отличается от SASRec? Целевая переменная: у SASRec — индекс объекта (softmax по каталогу), у TIGER — последовательность кодов; поэтому разные память, холодный старт и стоимость инференса.
  • Что сломается при смене энкодера контента? Все SID изменятся, и обученную модель придётся пересоздавать; это главный операционный риск подхода.
