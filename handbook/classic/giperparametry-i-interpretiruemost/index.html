Подбор гиперпараметров и интерпретируемость

Модель с настроенными гиперпараметрами и честной оценкой качества почти всегда полезнее модели с модной архитектурой и «угаданными» настройками. Вторая половина темы — зачем и как объяснять предсказания: от глобальной важности признаков до вклада каждого признака в отдельный ответ.

Параметры и гиперпараметры

Параметры модели (веса линейной регрессии, пороги в деревьях) находятся в процессе обучения минимизацией функции потерь на трейне. Гиперпараметры (глубина дерева, число деревьев, C и \gamma в SVM, скорость обучения, регуляризация) задаются до обучения и управляют сложностью модели; их нельзя выбирать по ошибке на трейне, потому что с ростом сложности она, как правило, только улучшается. Выбирают их по качеству на данных, которые модель не использовала при обучении.

Главная опасность — переобучение на валидацию: чем больше конфигураций перебрано, тем выше шанс, что лучшая из них выиграла случайно. Поэтому схема всегда трёхчастная: трейн → валидация (выбор гиперпараметров) → тест, который открывают один раз, в самом конце. Если после взгляда на тест вы поменяли модель, тест больше не тест.

Кросс-валидация

  • KFold: выборка делится на K частей, модель K раз обучается на K-1 частях и оценивается на оставшейся; оценка — среднее по фолдам (и стандартное отклонение — оно показывает, различаются ли конфигурации вообще).
  • StratifiedKFold: сохраняет долю классов в каждом фолде; обязателен при дисбалансе.
  • GroupKFold — если у одного пользователя или объекта несколько строк, и TimeSeriesSplit — для временных данных (валидация только «из будущего»). Обычный KFold на таких данных течёт и даёт завышенную оценку.

Вложенная кросс-валидация

Если выбрать лучшую конфигурацию по CV и сообщить её же CV-оценку, получится оптимистичная оценка: максимум по шуму смещён вверх. Nested CV разделяет эти задачи: внешний цикл оценивает качество процедуры «подбор + обучение»; во внутреннем цикле на обучающей части внешнего фолда подбираются гиперпараметры. Стоимость — K_{\text{out}}\times K_{\text{in}}\times |\text{сетка}| обучений, поэтому её используют для честного сравнения моделей на малых данных, а на больших хватает простого hold-out теста.

Правило одной стандартной ошибки

Разница между конфигурациями меньше шума CV — повод взять более простую (Hastie et al., ESL, §7.10). Берём лучший CV-результат, считаем стандартную ошибку среднего по фолдам \mathrm{SE}=s/\sqrt K и выбираем самую простую конфигурацию, чей результат не хуже \text{лучший}+\mathrm{SE} (для ошибки). Пример: Lasso на load_diabetes, 10-fold, RMSE по сетке \alpha (значения из запуска):

\alpha 0,003 0,03 0,1 0,3 1
RMSE 54,45 54,46 54,66 55,96 62,09

Лучший — \alpha=0{,}003 (54{,}45, \mathrm{SE}=1{,}45), порог 54{,}45+1{,}45=55{,}90. Самый сильный \alpha под порогом — 0{,}1 (RMSE 54{,}66, 7 ненулевых весов против 9); \alpha=0{,}3 порог превышает (55{,}96). Качество статистически то же, модель проще и устойчивее.

Стратегии поиска

Grid search перебирает декартово произведение сетки значений. Число конфигураций растёт экспоненциально с числом гиперпараметров, а равномерная сетка тратит много запусков на повторение одних и тех же значений важных параметров.

Random search (Bergstra & Bengio, 2012): значения каждого параметра сэмплируются независимо из заданного распределения (для C, \gamma, \eta — логравномерного). На практике для данной задачи важна лишь малая часть гиперпараметров («низкая эффективная размерность»). Тогда N случайных точек дают N разных значений каждого важного параметра, а сетка на d параметров — только N^{1/d} разных значений. Поэтому при одинаковом бюджете случайный поиск обычно находит конфигурацию не хуже.

Байесовская оптимизация: строится суррогатная модель \hat f(\theta) зависимости метрики от гиперпараметров по уже проведённым запускам (гауссов процесс, случайный лес, TPE), и следующая точка выбирается максимизацией acquisition function, балансирующей эксплуатацию (там, где суррогат предсказывает хорошо) и исследование (там, где неопределённость велика). Например, Expected Improvement: \mathrm{EI}(\theta)=\mathbb{E}\max(0, f(\theta)-f^*) для максимизируемой метрики, где f^* — лучшее найденное значение. TPE (Tree-structured Parzen Estimator, Bergstra et al., 2011) вместо p(y\mid\theta) моделирует p(\theta\mid y): делит запуски на «хорошие» и «плохие» по квантилю метрики, оценивает плотности l(\theta) и g(\theta) и выбирает точки с максимальным l(\theta)/g(\theta). Он работает с условными пространствами (параметры, существующие только при определённом выборе модели). Optuna (Akiba et al., 2019) — библиотека с TPE по умолчанию, динамическим определением пространства поиска через trial.suggest_* и отсечением неперспективных запусков.

Successive halving (Jamieson & Talwalkar, 2016) и Hyperband (Li et al., 2018): запустить много конфигураций на малом бюджете (эпохи, число деревьев, доля данных), оставить лучшую долю (половину или треть), увеличить бюджет во столько же раз и повторить. Hyperband перебирает несколько вариантов «сколько конфигураций против сколько бюджета на каждую», страхуясь от неудачного выбора. Подходит там, где качество при малом бюджете коррелирует с итоговым. В sklearn — HalvingGridSearchCV и HalvingRandomSearchCV (пока экспериментальные: нужен импорт sklearn.experimental.enable_halving_search_cv), в Optuna — HyperbandPruner.

Ранняя остановка как частный случай: число итераций бустинга или эпох нейросети — гиперпараметр, который не надо перебирать, достаточно следить за валидационной метрикой.

Практический рецепт: сначала random search или Optuna на 50–200 запусков по грубому диапазону, затем сузить диапазоны вокруг лучших значений; параметры вроде \eta и C — на логарифмической шкале; препроцессинг (масштабирование, отбор признаков) включать в Pipeline, чтобы он обучался внутри каждого фолда, а не на всей выборке.

Зачем нужна интерпретируемость

Отладка (модель использует артефакт вместо признака: утечку, водяной знак), доверие пользователей и экспертов, регуляторные требования (кредитный скоринг, медицина: право на объяснение решения), поиск причин дрейфа, а иногда и новое знание о данных. Объяснения бывают глобальными (какие признаки важны для модели в целом, как выглядит зависимость) и локальными (почему именно для этого объекта такой ответ). Простые модели (линейные, неглубокое дерево) интерпретируемы по построению; для остальных используются post-hoc методы, ниже.

Permutation importance

Берём обученную модель и отложенную выборку, перемешиваем значения признака j между объектами (разрываем его связь с таргетом) и смотрим, насколько упала метрика:

\mathrm{PI}_j = s(f, X, y) - \frac1R\sum_{r=1}^{R} s(f, X^{(j,r)}, y),

где s — метрика, X^{(j,r)} — выборка с перемешанным столбцом j (идея Breiman, 2001; в общем виде — Fisher, Rudin, Dominici, 2019, «model reliance»). Метод модельно-независим и измеряет реальную полезность признака для качества. Минусы: при сильной корреляции признаков перемешивание создаёт нереалистичные объекты, а важность делится между «двойниками» (модель берёт информацию из второго), так что обоих можно ошибочно счесть неважными; считать надо на валидации, иначе важности отражают переобучение.

PDP и ICE

Partial Dependence Plot (Friedman, 2001) показывает средний отклик модели при фиксированном значении признака x_S, усреднённый по остальным:

\mathrm{PD}(x_S) = \frac1n \sum_{i=1}^{n} f(x_S, x_C^{(i)}).

ICE (Goldstein et al., 2015) — те же кривые для каждого объекта по отдельности, без усреднения. Если кривые ICE идут в разные стороны, усреднение PDP скроет эффект: например, признак повышает отклик для одной группы и понижает для другой, а PDP выглядит плоским. Оба метода предполагают независимость x_S и x_C: при корреляции вычисляются предсказания в областях, где данных нет (альтернатива — ALE).

SHAP

Значения Шепли из теории кооперативных игр распределяют «выигрыш» (отклонение предсказания от среднего) между «игроками»-признаками. Вклад признака j — среднее его предельного вклада по всем порядкам добавления признаков:

\varphi_j = \sum_{S \subseteq F\setminus\{j\}} \frac{|S|!\,(p-|S|-1)!}{p!}\,\bigl[f(S\cup\{j\}) - f(S)\bigr],

где F — множество признаков, p=|F|, f(S) — ожидаемый ответ модели, если известны только признаки из S (остальные усреднены по фоновой выборке). Lundberg и Lee (2017) показали, что единственная аддитивная атрибуция с тремя естественными свойствами — локальная точность (вклады в сумме дают прогноз), отсутствующий признак получает нулевой вклад, согласованность (если модель изменилась так, что признак стал влиять сильнее, его вклад не уменьшается) — это значения Шепли:

f(x) = \varphi_0 + \sum_{j=1}^{p}\varphi_j, \qquad \varphi_0 = \mathbb{E} f(X).

Прямое вычисление перебирает 2^{p} коалиций, и каждое f(S) — ещё и усреднение по фоновой выборке: при p=30 это уже миллиард коалиций. Для деревьев TreeSHAP (Lundberg et al., 2020) считает точные значения за полиномиальное время, обходя структуру ансамбля; для остальных моделей есть KernelSHAP (взвешенная регрессия по сэмплам коалиций) и DeepSHAP.

Как читать:

  • force/waterfall plot для объекта: от базового значения \varphi_0 красные признаки поднимают прогноз, синие снижают, длина стрелки — величина вклада;
  • summary (beeswarm) plot: каждая точка — объект, ось x — SHAP-значение, цвет — значение признака; признаки упорядочены по среднему |\varphi_j|. Видно и важность, и направление: «большое значение признака → положительный вклад»;
  • dependence plot: \varphi_j от x_j, раскрашенный вторым признаком, показывает взаимодействия.

Для классификаторов на бустинге SHAP считается в пространстве логитов, а не вероятностей: вклады аддитивны именно там.

LIME

LIME (Ribeiro et al., 2016) объясняет один объект так: сгенерировать возмущения вокруг x, получить ответы модели, взвесить их близостью к x и обучить простую (линейную) модель — её коэффициенты и есть объяснение. Быстро и универсально, но нестабильно: результат зависит от выбора окрестности и сэмплирования. Для табличных данных с деревьями TreeSHAP точнее и надёжнее; LIME остаётся популярным для текстов и изображений.

Ловушки интерпретации

  • Важность ≠ причинность. Объяснение показывает, как модель использует признак, а не как устроен мир. Признак «число обращений в поддержку» может быть важен, но не причиной оттока.
  • Коррелированные признаки размывают и PI, и SHAP, и PDP; сгруппируйте их или анализируйте на уровне групп.
  • Объяснения зависят от модели и фона: разные модели с одинаковым качеством дают разные важности. Не стоит рассказывать «истину о данных», опираясь на одну модель.
  • Проверяйте объяснения на здравый смысл: если ID-подобный признак наверху рейтинга — это утечка.

Ловушки при подборе

  • Подбор по тесту или по тем же фолдам, по которым отчитываетесь, — оптимистичная оценка (см. nested CV).
  • Препроцессинг вне Pipeline — утечка в каждый фолд.
  • Равномерная шкала для C, \gamma, \eta вместо логарифмической.
  • Объяснение по трейну: важности и SHAP считают на отложенной выборке.
  • На собеседовании: почему random search обычно лучше grid search при том же бюджете (низкая эффективная размерность).
  • На собеседовании: зачем nested CV и сколько обучений она требует: K_{\text{out}}K_{\text{in}}|\text{сетка}|.
  • На собеседовании: чем permutation importance лучше MDI и чем SHAP отличается от LIME; что такое свойства Шепли; почему важность не равна причинности.

Код

python
import optuna, shap
from sklearn.datasets import load_breast_cancer
from sklearn.inspection import permutation_importance
from sklearn.model_selection import GridSearchCV, cross_val_score, train_test_split
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
import lightgbm as lgb

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, stratify=y, random_state=0)

# Grid search по пайплайну: масштабирование обучается внутри каждого фолда
pipe = Pipeline([("scaler", StandardScaler()), ("svm", SVC())])
grid = GridSearchCV(pipe, {"svm__C": [0.1, 1, 10, 100], "svm__gamma": [1e-3, 1e-2, 1e-1]},
                    cv=5, scoring="roc_auc").fit(X_tr, y_tr)
print(grid.best_params_, grid.best_score_)

# Nested CV: оценка процедуры подбора
print(cross_val_score(grid, X_tr, y_tr, cv=5, scoring="roc_auc").mean())

# Optuna (TPE) для LightGBM
def make(p):
    return lgb.LGBMClassifier(n_estimators=300, verbose=-1, learning_rate=p["lr"],
                              num_leaves=p["leaves"], reg_lambda=p["l2"],
                              colsample_bytree=p["colsample"])

def objective(trial):
    p = {"lr": trial.suggest_float("lr", 1e-2, 0.3, log=True),
         "leaves": trial.suggest_int("leaves", 4, 64, log=True),
         "l2": trial.suggest_float("l2", 1e-3, 10, log=True),
         "colsample": trial.suggest_float("colsample", 0.4, 1.0)}
    return cross_val_score(make(p), X_tr, y_tr, cv=5, scoring="roc_auc").mean()

study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=0))
study.optimize(objective, n_trials=50)
best = make(study.best_params).fit(X_tr, y_tr)

# Интерпретация на отложенной выборке
pi = permutation_importance(best, X_te, y_te, scoring="roc_auc", n_repeats=20, random_state=0)
print(sorted(zip(pi.importances_mean, X.columns))[-5:])

explainer = shap.TreeExplainer(best)
sv = explainer(X_te)                 # shap.Explanation, значения в логитах
shap.plots.beeswarm(sv)              # summary plot
shap.plots.waterfall(sv[0])          # один объект

Проверь себя

Почему нельзя сообщать CV-оценку лучшей конфигурации как качество модели?

Максимум по многим шумным оценкам смещён вверх: выбранная конфигурация отчасти выиграла случайно. Честную оценку даёт nested CV или нетронутый тест.

Почему при низкой эффективной размерности random search эффективнее grid search?

Сетка на d параметров даёт только N^{1/d} различных значений каждого параметра при N запусках, случайный поиск — N разных значений каждого важного параметра.

Чем TPE отличается от гауссовского процесса?

TPE моделирует p(\theta\mid y): делит запуски на хорошие и плохие по квантилю метрики, оценивает плотности l и g и берёт точки с максимальным l/g. Он работает с условными и категориальными пространствами.

Почему PDP может быть плоским при сильном влиянии признака?

Усреднение скрывает разнонаправленные эффекты: для одной группы объектов отклик растёт, для другой падает. ICE-кривые это показывают.

Что гарантируют значения Шепли и почему TreeSHAP быстрый?

Локальную точность (вклады дают прогноз минус среднее), нулевой вклад для неиспользуемого признака, согласованность. TreeSHAP использует структуру деревьев и считает точные значения за полиномиальное время вместо 2^p коалиций.
