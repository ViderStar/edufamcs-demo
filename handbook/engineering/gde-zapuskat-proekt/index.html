Где запускать свой проект: ноутбук дома, VPS, облака

11 мин АЛАртем Лебедевич 10 ноября 2026

Сервис, который работает только у вас на ноутбуке, в портфолио не считается: ссылку нельзя открыть, а на собеседовании вопрос «где это крутится и что будет, если упадёт» остаётся без ответа. Эта статья — карта вариантов для студенческого проекта: от бесплатной демо-страницы до арендованного сервера. Выбор определяется тремя вещами: нужен ли вам постоянный адрес, нужна ли своя база данных и сколько вы готовы платить деньгами и временем на обслуживание.

Рабочий пример сквозной для раздела: маленький сервис предсказаний (FastAPI с /predict и /healthz в Docker, рядом Postgres, всё описано в compose.yaml; см. Docker Compose). Всё, что ниже, — способы показать его миру.

Четыре семейства вариантов

Вариант Что получаете Цена вопроса
Демо-хостинг Страница с моделью, URL «из коробки» Нет своего Postgres, нет контроля над средой
Домашняя машина + туннель Полный compose.yaml, свой домен Электричество и интернет — на вас
VPS Всё то же, но в дата-центре Ежемесячная плата и администрирование
Облачные платформы и free tier Управляемые сервисы Ограничения, сон, привязка карты

Демо-хостинг

Подходит, когда цель — показать модель, а не сервис. Hugging Face Spaces хранят код в git-репозитории и пересобираются на каждый коммит; SDK — Gradio, Docker или статический HTML. По документации Hugging Face, статические Spaces бесплатны для всех, а Gradio- и Docker-Spaces требуют платного плана, и на бесплатном железе Space «засыпает» при простое. Streamlit Community Cloud разворачивает Streamlit-приложение прямо из репозитория GitHub. GitHub Pages отдаёт только статику: подойдёт для отчёта или для фронтенда, который ходит в API где-то ещё. Условия таких площадок меняются, поэтому перед выбором откройте актуальную страницу с тарифами и лимитами.

Ограничение общее: это витрина. Фоновые задачи, свой Postgres и наблюдаемость вы здесь не получите.

Домашняя машина и туннель

Старый ноутбук или мини-ПК с Linux, который включён постоянно, — самый дешёвый способ получить настоящий сервер. Проблема в том, что у домашнего провайдера обычно нет белого IP, а проброс портов на роутере делает вашу домашнюю сеть мишенью. Решение — туннель. cloudflared на вашей машине сам открывает исходящие соединения до сети Cloudflare; запросы пользователей приходят через них. Входящие порты на роутере не нужны, наружу ничего не торчит, а HTTPS-сертификат для вашего домена обслуживает Cloudflare. Что нужно: домен, DNS которого управляется в Cloudflare, и аккаунт. Что ломается: отключили электричество или интернет — сервис недоступен; динамика домашней сети вас не касается, но надёжность дата-центра вы теряете.

VPS

VPS — виртуальная машина с публичным IP, в которой вы root. Для сервиса из нашего примера обычно хватает 1–2 ГБ памяти: FastAPI с небольшой sklearn- или GBDT-моделью и Postgres помещаются; PyTorch-модель на сотни мегабайт, эмбеддинги в памяти или несколько воркеров уже упираются в предел. После выдачи сервера сразу:

bash
# на сервере под root
adduser deploy && usermod -aG sudo deploy
# на ноутбуке
ssh-keygen -t ed25519 -C "vps"
ssh-copy-id deploy@SERVER_IP
# на сервере под deploy, проверив вход по ключу во втором окне
echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/00-no-password.conf
sudo sshd -t && sudo systemctl restart ssh
sudo ufw default deny incoming
sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp
sudo ufw enable
sudo apt install -y unattended-upgrades
# после установки Docker: sudo usermod -aG docker deploy (группа docker = права root)

Порядок важен: сначала создайте пользователя deploy (под root) и скопируйте ему ключ, убедитесь, что вход по ключу работает во втором окне терминала, и только потом отключайте пароли. Настройку кладём в sshd_config.d/00-no-password.conf, а не правим sshd_config через sed: на образах Ubuntu у облачных провайдеров файл 50-cloud-init.conf может включать парольный вход обратно, а сервер читает файлы из sshd_config.d по алфавиту и применяет первое значение параметра, поэтому 00- побеждает. Перед перезапуском sshd -t проверяет конфиг. В группу docker пользователя добавляют после установки Docker (до этого группы нет); она равна правам root, поэтому не выдавайте её посторонним.

Docker обходит ufw

Опубликованный порт (ports: "5432:5432") Docker открывает через собственные правила iptables, мимо правил ufw. Привязывайте порты к 127.0.0.1 в compose.yaml и выставляйте наружу только reverse proxy.

Free tier и его подводные камни

Облачные провайдеры дают бесплатные уровни. Типичные ловушки, которые нужно искать в условиях конкретного провайдера: инстанс засыпает после простоя и просыпается десятки секунд; бесплатная база данных истекает или удаляется через определённый срок; нужна банковская карта, и при выходе за лимит списываются деньги; квоты по трафику, часам и памяти; аккаунт могут заблокировать за неактивность. Конкретные цифры здесь не приводятся намеренно: они меняются, сверяйте их на странице цен провайдера в день выбора. Установите бюджетный алерт и убедитесь, что понимаете, что произойдёт при превышении лимита.

Домен, DNS и HTTPS

DNS переводит имя в адрес. Запись A сопоставляет имя IPv4-адресу (api.example.com → 203.0.113.10), AAAA — IPv6, CNAME — делает имя псевдонимом другого имени (так вы направляете www на основной домен или на адрес платформы). При схеме с туннелем запись создаётся на вашем домене автоматически и указывает на туннель.

Дальше на сервере стоит reverse proxy (Caddy, nginx, Traefik): он слушает 80/443, терминирует TLS (расшифровывает HTTPS, получая и продлевая сертификат, например у Let's Encrypt) и пересылает запрос приложению по обычному HTTP внутри машины. Самый короткий вариант — Caddy:

text
api.example.com {
    reverse_proxy 127.0.0.1:8765
}

Приложению при этом незачем знать про сертификаты, а наружу торчат только порты прокси.

Минимальный чек-лист продакшена

  • Секреты — в переменных окружения или файле вне git, не в образе и не в репозитории.
  • Бэкапы и проверка восстановления. pg_dump по расписанию в другое место (не на тот же диск) и хотя бы раз реальный restore в чистую базу. Бэкап, который не восстанавливали, — гипотеза.
  • Healthcheck и внешний uptime-монитор. /healthz внутри Docker и проверка снаружи (UptimeRobot или аналог) с оповещением в Telegram или на почту.
  • Ротация логов: без лимита docker logs растут, пока не забьют диск (подробнее).
  • Политика перезапуска: restart: unless-stopped в compose.yaml.
  • Не root в контейнере (USER в Dockerfile) и привязка к 127.0.0.1 за прокси.
  • Обновления: образ базы и ОС обновляются, версии зафиксированы.

Деньги и GPU

Считайте не только ежемесячную плату, но и своё время: бесплатный вариант, который засыпает, и платный за несколько долларов в месяц, который стабильно работает, — разный опыт для посетителя вашего портфолио. Для проекта на резюме обычно достаточно одного небольшого VPS или домашнего сервера с туннелем.

GPU нужны для обучения, а не для обслуживания: обучайте на Colab, Kaggle или арендованной по часам GPU и выключайте её, а в сервис отдавайте готовый артефакт. Инференс небольшой модели на CPU укладывается в задержки учебного проекта; GPU в сервисе оправдан для больших нейросетей и высокого RPS, и тогда он стоит заметно дороже всего остального вместе взятого.

Не плодите сущности

Начните с одного компьютера и compose.yaml. Kubernetes, оркестраторы и managed-базы появятся, когда у вас будет нагрузка, которая их требует, а не раньше.

Ловушки

  • Порт Postgres, опубликованный на 0.0.0.0 без файрвола: через несколько часов в логах появляются брутфорс-попытки.
  • Пароль root вместо ключа; .env в git; секреты в Dockerfile (остаются в слоях образа).
  • Бесплатный инстанс «спит», и первый запрос ревьюера падает по таймауту.
  • Бэкап на тот же диск, что и база.
  • Деплой «руками по ssh» без записи шагов: через месяц вы не воспроизведёте его сами.
  • На собеседовании спрашивают: как открыть сервис наружу безопасно; что такое TLS termination; зачем reverse proxy; как узнать, что сервис упал, раньше пользователя; чем VPS отличается от контейнера.

Проверь себя

Чем туннель Cloudflare безопаснее проброса порта на роутере?

Соединение инициирует ваша машина, поэтому на роутере не открыт ни один входящий порт; домашняя сеть недоступна из интернета напрямую, а TLS на границе обслуживает Cloudflare.

Что делает reverse proxy и где заканчивается HTTPS?

Принимает запросы на 80/443, терминирует TLS и пересылает их приложению по HTTP на 127.0.0.1. Внутри машины трафик до приложения не шифруется, и это нормально, пока порт не выставлен наружу.

Почему `ports: "5432:5432"` опасно даже при включённом ufw?

Docker добавляет правила iptables в обход ufw, и порт оказывается открыт. Нужно привязывать к 127.0.0.1 или не публиковать порт вовсе, оставив доступ внутри сети compose.

Чем бэкап отличается от проверенного бэкапа?

Проверенный бэкап восстанавливали в чистую базу и убедились, что данные и схема на месте. Файл дампа без этого может оказаться пустым или несовместимым.

Где обучать модель, а где её обслуживать?

Обучение — на временно арендованной или бесплатной GPU (Colab, Kaggle, почасовая аренда), обслуживание — на дешёвой CPU-машине с готовым артефактом, пока модель и RPS позволяют.
