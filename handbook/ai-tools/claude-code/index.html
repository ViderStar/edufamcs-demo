Claude Code: установка, режимы, CLAUDE.md

Claude Code — кодовый агент Anthropic: он читает репозиторий, правит файлы, запускает команды и работает с git. Основной интерфейс — терминал, но тот же движок доступен в расширениях для VS Code и JetBrains, в десктопном приложении и в вебе. Эта статья — рабочий минимум: установка, цикл «разведка → план → реализация → проверка», режимы разрешений, файл CLAUDE.md и управление контекстом. Продукт быстро меняется, поэтому источник истины — официальная документация (ссылки внизу); ниже только то, что сверено с ней на ноябрь 2026.

Установка и первый запуск

Рекомендуемый способ для macOS, Linux и WSL — установочный скрипт; для Windows PowerShell есть свой, а также Homebrew и WinGet:

bash
curl -fsSL https://claude.ai/install.sh | bash
powershell
irm https://claude.ai/install.ps1 | iex
bash
brew install --cask claude-code

Проверка: откройте новое окно терминала и выполните claude --version. Запуск — из каталога проекта:

bash
cd /path/to/your/project
claude

При первом запуске откроется вход в браузере. Нужна подписка Claude (Pro, Max и др.), аккаунт Claude Console с API-доступом или доступ через поддерживаемого облачного провайдера. Установка скриптом обновляется автоматически, Homebrew и WinGet — вручную.

Первые вопросы безопасны: «what does this project do?», «explain the folder structure». /help покажет команды, /resume продолжит прошлую беседу.

Рабочий цикл: разведка, план, реализация, проверка

  1. Разведка. Попросите изучить код и ничего не менять: «как устроено обучение, где считаются метрики?». Агент читает файлы сам, указывать каждый не нужно.
  2. План. Для всего нетривиального — в режиме планирования (ниже). Прочитайте план, поправьте до начала правок.
  3. Реализация. Небольшими шагами; после каждого — коммит.
  4. Проверка. Агент должен запустить тесты и линтер и показать результат; вы просматриваете дифф.

Документация формулирует это жёстко: если у агента нет проверки, возвращающей «прошло/не прошло», проверяющим становитесь вы. Лучшая строка в CLAUDE.md — команда, которая запускает проверку.

Режимы разрешений

Режим определяет, что агент делает без вашего подтверждения. Переключение в сессии — Shift+Tab; при запуске — флаг --permission-mode.

Режим (значение) Что выполняется без вопросов
default («Manual») только чтение; правки, команды и сеть — с подтверждением
acceptEdits чтение, правка файлов и типовые файловые команды (mkdir, mv, cp…) в рабочих каталогах
plan чтение; агент исследует и предлагает план, исходники не правит
auto всё, но отдельная модель-классификатор проверяет действия в фоне
dontAsk только чтение и заранее разрешённое; всё остальное отклоняется
bypassPermissions всё; только для изолированного контейнера или ВМ

В новых версиях интерактивные сессии по умолчанию стартуют в auto; в старых это зависело от тарифа, так что проверьте строку состояния. bypassPermissions (флаг --dangerously-skip-permissions) на рабочей машине не используйте.

Режим планирования: войти можно через Shift+Tab до индикатора «plan mode on», командой /plan (можно сразу с описанием: /plan fix the auth bug) или флагом claude --permission-mode plan. Когда план готов, агент предложит одобрить его и перейти к правкам; Ctrl+G открывает план в вашем редакторе.

Списки разрешений задают конкретные команды, которые можно не подтверждать, в .claude/settings.json (проект, коммитится в git), .claude/settings.local.json (личное) или ~/.claude/settings.json (все проекты):

json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Bash(git push *)"
    ]
  }
}

Это пример из документации; для питонового проекта вместо npm run вы разрешите, например, Bash(uv run pytest *). Запрещающее правило сильнее разрешающего. Интерактивно правила смотрят и правят через /permissions. Звёздочку ставьте после подкоманды: Bash(git log *) разрешает только git log, а Bash(git *) — любую git-команду.

CLAUDE.md: постоянные инструкции

Каждая сессия начинается с пустого контекста. CLAUDE.md — markdown-файл, который подгружается в начало каждой сессии. Расположения:

  • ./CLAUDE.md или ./.claude/CLAUDE.md — инструкции проекта, общие для команды через git;
  • ~/.claude/CLAUDE.md — ваши личные правила для всех проектов;
  • ./CLAUDE.local.md — личное для проекта, добавьте в .gitignore.

Команда /init генерирует стартовый файл, изучив репозиторий: команды сборки и тестов, структуру, соглашения. Если файл уже есть, она предложит улучшения. Дальше правьте руками: оставьте то, чего из кода не узнать.

Что писать, и конкретно, чтобы это можно было проверить:

markdown
# Проект: churn-model

## Команды
- Тесты: `uv run pytest -x -q`; один файл: `uv run pytest tests/test_metrics.py`
- Линтер: `uv run ruff check .`
- Обучение (дешёвый профиль): `uv run python train.py --config configs/smoke.yaml`

## Соглашения
- Метрики живут в `src/metrics.py`, с тестами в `tests/test_metrics.py`
- Разбиение по времени: `src/split.py`; случайный split для этих данных запрещён

## Не трогать
- `data/raw/` — только чтение; `configs/prod.yaml` без моего подтверждения не менять

Правила: цель — короче 200 строк (длиннее — хуже соблюдаются и дороже по контексту), без противоречий, без многошаговых процедур. Многошаговое лучше вынести в навык. Помните: CLAUDE.md — контекст, а не принуждение; то, что нельзя нарушить ни при каких условиях, закрывайте запретом в разрешениях или хуком. Если в репозитории уже есть AGENTS.md, Claude Code читает его, когда CLAUDE.md нет; детали — в статье про Codex.

Полезные команды

Команда Зачем
/init создать стартовый CLAUDE.md
/clear новая беседа с пустым контекстом
/compact [инструкции] сжать историю, можно указать фокус: /compact focus on the API changes
/context показать, что занимает окно
/resume, claude --continue вернуться к прошлой беседе
/rewind (или двойной Esc) откатить беседу и/или правки к прошлой точке
/diff просмотреть изменения в рабочем дереве
/review ревью диффа или PR
/permissions, /model, /memory, /usage разрешения, выбор модели, правка CLAUDE.md, расход

Откат (checkpoints) покрывает только файлы; действия во внешних системах он не вернёт.

Управление контекстом

Одна задача — одна сессия: закончили, сделали /clear или начали новую. Не перетаскивайте в новую задачу чужую историю. Окно заполняется выводами команд и прочитанными файлами; /context покажет, что съело место. При приближении к лимиту история сжимается автоматически, но детали из начала разговора могут потеряться, поэтому правила держите в CLAUDE.md, а не в чате (корневой CLAUDE.md перечитывается после компактации). Тяжёлую разведку можно поручить субагенту: он работает в своём окне и возвращает резюме (подробнее).

Git, PR и неинтерактивный режим

Агент умеет git: «what files have I changed?», «commit my changes with a descriptive message», «create a pr». PR он создаёт через gh pr create или glab mr create, если инструмент установлен; читайте описание перед отправкой. Для параллельных задач есть claude --worktree <имя> — отдельная рабочая копия на своей ветке.

Для скриптов и CI — флаг -p: claude -p "query" выполняет один запрос и завершается. С --output-format json вы получаете структурированный ответ, с --allowedTools заранее разрешаете инструменты:

bash
claude -p "Run the test suite and fix any failures" --allowedTools "Bash,Read,Edit"

В CI документация советует добавлять --bare, чтобы запуск не подхватывал чужие хуки и CLAUDE.md с машины. Ключи и токены — только через переменные окружения.

Пример сессии: добавить метрику и тест

Репозиторий с моделью оттока; хотим добавить recall@k в src/metrics.py.

text
> Изучи src/metrics.py и tests/test_metrics.py. Как считаются текущие метрики и как они тестируются? Ничего не меняй.

Затем Shift+Tab до режима планирования:

text
> Добавь recall@k: доля релевантных объектов среди топ-k по скору, усреднённая по пользователям. Пользователей без релевантных пропускать. Сначала план: сигнатура, обработка ничьих по скору, тесты.

Читаем план: проверяем определение (знаменатель, ничьи), правим словами и одобряем. Дальше:

text
> Реализуй по плану. Тесты на ручном примере из 5 объектов, где ответ посчитан мной вручную (в тесте — мои числа). Запусти uv run pytest tests/test_metrics.py и покажи вывод.

Вручную: /diff, затем сверка с вашим расчётом на бумаге и, при желании, с независимой реализацией (например, из библиотеки для ранжирования). Только после этого — commit this with a descriptive message. Ключевое: ожидаемые значения в тесте вы задали сами, а не позволили агенту вывести их из своего же кода.

Ловушки

  • Режим без подтверждений на рабочем ноутбуке с доступом к ключам и данным.
  • Огромный CLAUDE.md с историей проекта; противоречивые правила.
  • Одна бесконечная сессия на всё: контекст забит, ранние решения потеряны.
  • Принятие правки без /diff; агент мог тихо изменить тест или конфиг.
  • Вставка секретов в промпт; ключи только в переменных окружения.
  • Отсутствие команды проверки в CLAUDE.md: агент «закончит», ничего не запустив.

Проверь себя

Зачем нужен режим планирования и как в него войти?

Агент исследует и предлагает план, не правя исходники, пока вы не одобрите. Вход: Shift+Tab, /plan или claude --permission-mode plan.

Что должно быть в CLAUDE.md и чего там быть не должно?

Должно: команды тестов и линтера, соглашения, зоны «не трогать», проверяемыми формулировками. Не должно: длинные процедуры, пересказ кода, противоречия; ориентир — меньше 200 строк.

Чем `/clear` отличается от `/compact`?

/clear начинает новую беседу с пустым контекстом, /compact сжимает текущую историю в резюме и продолжает её.

Почему deny-правило надёжнее просьбы в CLAUDE.md?

CLAUDE.md — контекст, который модель может не учесть; правила разрешений применяет сама обвязка, и запрет сильнее разрешения.

Как сделать, чтобы агент сам проверял свою работу?

Дать команду с результатом «прошло/не прошло» (тесты, линтер, скрипт сравнения), записать её в CLAUDE.md и потребовать показать вывод.
