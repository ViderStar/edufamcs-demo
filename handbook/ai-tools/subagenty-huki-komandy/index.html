Субагенты, хуки и слэш-команды

11 мин АЛАртем Лебедевич 10 ноября 2026

Кроме скиллов и MCP, у кодовых агентов есть ещё три рычага. Субагент — отдельный «исполнитель» со своим контекстным окном, инструментами и инструкцией. Слэш-команда — сохранённый запрос, который вы вызываете вручную. Хук — команда оболочки, которая выполняется на событие всегда, независимо от настроения модели. Набор функций у разных инструментов различается и меняется; формат ниже взят из документации Claude Code и Codex на ноябрь 2026, и именно она — источник истины.

Субагенты

Субагент получает собственное окно контекста. Он не видит вашего диалога и файлов, которые агент уже прочёл: основной агент пишет ему задание, субагент работает по нему и возвращает только итоговое резюме. Отсюда плюсы и цена.

Когда это окупается:

  • Широкий поиск. «Найди все места, где считается метрика» — сотни прочитанных файлов остаются в чужом контексте, в основной приходит абзац.
  • Независимое ревью. Свежий контекст не разделяет ваших допущений и не защищает уже написанное.
  • Параллельная работа над независимыми кусками.

Цена: субагент знает только то, что ему написали (плохое задание — плохой результат), вы видите резюме, а не ход рассуждений, и токенов уходит больше, чем в однопоточной работе (Codex в документации говорит об этом прямо). Для задачи на три файла делегировать не нужно.

Свой субагент в Claude Code

Это Markdown-файл с YAML-заголовком в .claude/agents/ (проект) или ~/.claude/agents/ (все проекты). Заголовок задаёт конфигурацию, тело становится системным промптом. Обязательны name и description; из необязательных полезны tools (белый список), disallowedTools, model, maxTurns, skills, isolation: worktree, background. Если tools не указать, субагент наследует все доступные инструменты.

Пример — скептик для эксперимента: читает, но ничего не меняет.

markdown
---
name: experiment-skeptic
description: Независимое ревью дизайна эксперимента или ноутбука до долгого запуска. Использовать перед дорогим прогоном и когда нужен взгляд без доверия к автору.
tools: Read, Grep, Glob
model: inherit
---

Ты скептик-рецензент ML-эксперимента. Автор уверен, что всё верно; твоя
задача — найти, что сделает результат ложным или бесполезным.

Тебе дадут путь к ноутбуку или скрипту и формулировку гипотезы. Больше ты
ничего не знаешь — не додумывай, читай файлы.

Проверь по порядку:
1. Утечки: fit препроцессинга до разбиения, признаки из будущего, пересечение
   пользователей/объектов между train и valid, агрегаты по всей таблице.
2. Валидация: соответствует ли разбиение реальному использованию (время, группы);
   одинаковы ли условия у baseline и новой модели; шум метрики (seeds, размер valid).
3. Метрика: считается ли то, что заявлено; можно ли её «улучшить» без пользы.
4. Что в результате было бы опровержением гипотезы — и проверяется ли оно.

Формат ответа: список находок по убыванию серьёзности. У каждой — где
(файл, ячейка), почему опасно, как проверить. В конце — что ты не смог проверить.
Не предлагай переписывать код целиком и ничего не правь.

Вызвать можно фразой «используй субагента experiment-skeptic для ноутбука nb/ranker.ipynb» или через @-упоминание. Фразы вроде «use proactively» в описании поощряют автоматическое делегирование. Для одного запуска определения можно передать JSON-ом через claude --agents '{...}'; встроенные субагенты (Explore, Plan, general-purpose) уже есть.

Codex

Субагенты там тоже есть: отдельные TOML-файлы в ~/.codex/agents/ или .codex/agents/, обязательные поля name, description и developer_instructions, дополнительно можно задать модель и уровень рассуждений. Песочница и политика одобрений наследуются от родителя и в файле агента не переопределяются. Вызывают просьбой в запросе («запусти двух агентов…»), в CLI /subagents переключает между потоками.

Слэш-команды

Это сохранённый запрос, который вы вызываете по имени. В Claude Code команды слились со скиллами: файл .claude/commands/smoke.md и скилл .claude/skills/smoke/SKILL.md создают одну и ту же /smoke; при совпадении имён побеждает скилл. Подпапки превращаются в двоеточия: commands/frontend/component.md — это /frontend:component. Заголовок у файла команды — тот же, что у скилла, без name и paths.

markdown
---
description: Дешёвый прогон текущего ноутбука с проверкой, что дошли до метрики
---

Запусти ноутбук, на который я указал, в режиме SMOKE=1 (малая выборка, 1 эпоха).
Не правь ноутбук. Верни: время, метрику на valid, предупреждения и первую ошибку.

В Codex аналог — кастомные промпты, ~/.codex/prompts/*.md с description: и argument-hint: в заголовке и плейсхолдерами $1…$9, $ARGUMENTS; вызов — /prompts:имя. Но документация объявляет их устаревшими в пользу скиллов (они ещё и не делятся через репозиторий). См. скиллы.

Хуки

Хук — команда, которую инструмент выполняет на событие: перед или после вызова инструмента, при остановке, при уведомлении. В отличие от просьбы в CLAUDE.md, хук срабатывает всегда: инструкции агент может «забыть», хук — нет. Типичное: автоформатирование после правки, блокировка опасных команд, уведомление «агент закончил».

Конфигурация в Claude Code (~/.claude/settings.json, .claude/settings.json, .claude/settings.local.json) — три уровня: событие → группа с matcher → обработчик. Событий десятки; важнейшие: PreToolUse, PostToolUse, Notification, Stop, SessionStart, UserPromptSubmit. Хук получает JSON на stdin (tool_name, tool_input, cwd…). Коды выхода: 0 — всё хорошо; 2 — блокирующая ошибка, текст из stderr возвращается агенту (для PreToolUse вызов отменяется); любой другой — не блокирует, показывается предупреждение. Пример из документации — запрет rm -rf:

json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
bash
#!/bin/bash
COMMAND=$(jq -r '.tool_input.command')

if echo "$COMMAND" | grep -q 'rm -rf'; then
  jq -n '{
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "Destructive command blocked by hook"
    }
  }'
else
  exit 0  # решения нет, работает обычная проверка разрешений
fi

Скрипту нужен chmod +x и jq. Для форматирования подойдёт тот же шаблон на PostToolUse с "matcher": "Write|Edit" и вашим скриптом: этот хук не может отменить правку, она уже сделана, но может вернуть замечания агенту. Хук Stop с кодом 2 не даёт агенту остановиться — так делают «не заканчивай, пока тесты не зелёные», и так же легко устроить бесконечный цикл, поэтому ставьте условие выхода.

В Codex хуки описаны в ~/.codex/hooks.json, <repo>/.codex/hooks.json или в config.toml; формат тот же (событие → matcher → обработчик type: "command"), PreToolUse блокируется кодом 2 или тем же permissionDecision: "deny". Проектные хуки грузятся только в доверенном проекте и до запуска проверяются командой /hooks. Набор событий у Codex меньше и отличается; смотрите актуальный список.

Хук — это код, который вы запускаете

Хуки из чужого репозитория выполняются с вашими правами. Читайте .claude/settings.json и .codex/ до первого запуска агента в незнакомом проекте.

Фоновые, headless и по расписанию

Агента можно запускать без интерактива: claude -p "…" (с --output-format json, --allowedTools, --permission-mode) и codex exec "…" (по умолчанию песочница read-only; --sandbox workspace-write разрешает запись). Для скриптов и CI Claude Code рекомендует --bare: он не подхватывает хуки, скиллы, MCP-серверы и CLAUDE.md из окружения, и результат не зависит от машины. Без --bare режим -p исполняет хуки и подключает серверы проекта без вопросов. Субагенты, которых Claude запускает из основного диалога, уже стартуют в фоне; поле background: true оставляет субагента в фоне, даже когда Claude просят дождаться результата. Повторяющиеся запуски есть в обоих: в Claude Code — /loop (повтор в сессии) и /schedule (облачные задачи по расписанию), в Codex — Scheduled tasks в приложении ChatGPT и вебе (не в CLI). Формат быстро меняется: смотрите актуальные страницы. Как применять всё это к долгим ML-прогонам — в статье агент в ML-проекте.

Ловушки

  • Делегировать мелочь: расход токенов и потеря контекста перевешивают выгоду.
  • Короткое задание субагенту («проверь это»): он не знает ни цели, ни ограничений. Давайте путь, гипотезу, критерий готовности.
  • Верить резюме субагента без проверки: он тоже может ошибаться; требуйте ссылки на файлы и строки.
  • Хук без тайм-аута или с побочными эффектами; Stop-хук без условия выхода.
  • Опасное правило держат только в CLAUDE.md: оно подсказка, хук — гарантия.
  • Давать субагенту-рецензенту права на запись: ревьюер правит «заодно», и независимость пропадает.

Проверь себя

Что видит субагент и что возвращает?

Свой системный промпт, задание от основного агента и базовые сведения об окружении; историю диалога он не видит. Возвращает итоговое резюме, остальной вывод остаётся в его контексте.

В каких случаях делегирование окупается, а в каких нет?

Окупается: широкий поиск, независимое ревью, параллельные независимые задачи. Не окупается: небольшая задача, где результат нужен целиком и контекст общий.

Чем хук отличается от строки в `CLAUDE.md`?

CLAUDE.md — текст в контексте, модель может не последовать ему. Хук — команда, которую инструмент выполняет на событие всегда; блокирующий хук отменяет вызов.

Что означают коды выхода хука `PreToolUse` в Claude Code?

0 — успех, при JSON в stdout можно вернуть решение; 2 — блокировка, stderr уходит агенту; прочие — неблокирующая ошибка, действие продолжается.

Почему рецензенту-скептику не дают инструменты записи?

Чтобы он только искал проблемы: если он умеет править, он смешивает ревью с исправлением, и автор получает результат, который никто не проверял независимо.
