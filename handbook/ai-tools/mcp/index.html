MCP: подключаем инструменты и данные

11 мин АЛАртем Лебедевич 10 ноября 2026
Содержание Какую проблему решаетУстройствоПодключение в Claude CodeПодключение в CodexМинимальный сервер на PythonЦена в контекстеБезопасностьКогда лучше CLI и скиллЛовушкиПроверь себяЧто почитать

Model Context Protocol (MCP) — открытый протокол, по которому ИИ-приложение подключается к внешним инструментам и данным: базе, трекеру, браузеру, вашей собственной функции. Без него каждая пара «клиент × система» требовала бы отдельной интеграции; с ним сервер пишется один раз и работает в любом клиенте с поддержкой протокола. Ниже — устройство, подключение в Claude Code и Codex, минимальный сервер на Python (проверен на mcp 2.3.0) и то, чем MCP опасен. Детали меняются быстро; источник истины — документация по ссылкам в конце.

Какую проблему решает

N инструментов и M клиентов (Claude Code, Codex, IDE, чат) без общего протокола дают N × M адаптеров. С MCP — N серверов и M клиентов, все говорят на одном языке: протокол описывает, как клиент узнаёт, что умеет сервер, и как вызывает его функции.

Устройство

Три роли. Хост — ИИ-приложение (Claude Code, Codex). Клиент — компонент хоста, держащий соединение с одним сервером; хост создаёт по клиенту на каждый сервер. Сервер — программа, отдающая контекст. В основе JSON-RPC 2.0; протокол делится на слой данных и слой транспорта.

Сервер предлагает три примитива:

  • tools — функции, которые вызывает модель (запрос в базу, вызов API);
  • resources — данные для контекста (содержимое файла, схема таблицы);
  • prompts — готовые шаблоны запросов.

Транспорта два. stdio: хост запускает сервер подпроцессом и общается через stdin/stdout; обычно это локальный сервер для одного клиента. Streamable HTTP: сервер доступен по адресу и обслуживает многих клиентов, поддерживаются токены, ключи и заголовки, рекомендуется OAuth. Транспорт SSE в документации Claude Code помечен устаревшим.

Подключение в Claude Code

Команды ниже — из документации Claude Code.

bash
# удалённый сервер по HTTP
claude mcp add --transport http <имя> <url>

# локальный stdio-сервер: всё после -- передаётся серверу как есть
claude mcp add --env TABLES_DB=/abs/path/data.db --transport stdio tables \
  -- uv run --with mcp python /abs/path/table_server.py

claude mcp list
claude mcp get tables
claude mcp remove tables

Области: local (по умолчанию, только вы и этот проект, хранится в ~/.claude.json), project (файл .mcp.json в корне репозитория, общий для команды), user (все ваши проекты). Внутри сессии /mcp показывает состояние серверов. Формат .mcp.json; значения секретов подставляются из окружения через ${VAR}, в репозиторий они не попадают:

json
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}

Подключение в Codex

Файл конфигурации — ~/.codex/config.toml или .codex/config.toml в доверенном проекте; CLI, IDE-расширение и приложение читают одну конфигурацию.

bash
codex mcp add <имя> --env VAR1=VALUE1 -- <команда stdio-сервера>
codex mcp list
toml
[mcp_servers.tables]
command = "uv"
args = ["run", "--with", "mcp", "python", "/abs/path/table_server.py"]
env_vars = ["TABLES_DB"]        # имена переменных, которые пробросить серверу

[mcp_servers.api]
url = "https://example.com/mcp"
bearer_token_env_var = "API_TOKEN"
enabled_tools = ["search"]      # белый список инструментов

Если передать --oauth-client-secret, Codex сохранит его в config.toml (mcp_servers.<имя>.oauth.client_secret), поэтому такой файл не коммитят; OAuth-токены хранятся отдельно (mcp_oauth_credentials_store: keyring или файл).

Минимальный сервер на Python

Задача: дать агенту безопасный способ посмотреть таблицу — схему, долю пропусков, несколько строк — без права записи. Нужен Python 3.11+ и пакет mcp.

Версии SDK

В mcp 2.x класс FastMCP переименован в MCPServer (from mcp.server import MCPServer), модуль mcp.server.fastmcp исчез. Большинство учебников написано под 1.x; для старого кода закрепите mcp<2. Код ниже запущен на mcp 2.3.0.

python
import os
import re
import sqlite3
from pathlib import Path

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError

DB_PATH = Path(os.environ.get("TABLES_DB", "data.db")).resolve()
IDENT = re.compile(r"^[A-Za-z_][A-Za-z0-9_]*$")

mcp = MCPServer("tables")


def connect() -> sqlite3.Connection:
    # mode=ro: сервер физически не может писать, что бы ни попросила модель
    return sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)


@mcp.tool()
def describe_table(table: str, sample_rows: int = 3) -> dict:
    """Describe a table in the local SQLite database: columns, types,
    row count, NULL share per column and a few sample rows.
    Read-only. Use it before writing any code that touches the table."""
    if not IDENT.match(table):
        raise ToolError("table name must be a plain identifier")
    sample_rows = max(0, min(sample_rows, 10))
    with connect() as db:
        cols = db.execute(f'PRAGMA table_info("{table}")').fetchall()
        if not cols:
            raise ToolError(f"no such table: {table}")
        n = db.execute(f'SELECT COUNT(*) FROM "{table}"').fetchone()[0]
        out_cols = []
        for _, name, typ, *_ in cols:
            nulls = db.execute(
                f'SELECT COUNT(*) FROM "{table}" WHERE "{name}" IS NULL'
            ).fetchone()[0]
            out_cols.append({"name": name, "type": typ,
                             "null_share": round(nulls / n, 4) if n else None})
        cur = db.execute(f'SELECT * FROM "{table}" LIMIT {sample_rows}')
        head = [dict(zip([c[0] for c in cur.description], r)) for r in cur.fetchall()]
    return {"table": table, "rows": n, "columns": out_cols, "sample": head}


if __name__ == "__main__":
    mcp.run()  # по умолчанию stdio

Проверка без всякого агента: тот же SDK содержит клиента, который запускает сервер подпроцессом.

python
import asyncio, json
from mcp import Client
from mcp.client.stdio import StdioServerParameters

async def main():
    params = StdioServerParameters(
        command="uv", args=["run", "--with", "mcp", "python", "table_server.py"])
    async with Client(params) as c:
        print([t.name for t in (await c.list_tools()).tools])
        r = await c.call_tool("describe_table", {"table": "ratings", "sample_rows": 1})
        print(json.loads(r.content[0].text)["rows"])
        r = await c.call_tool("describe_table", {"table": "ratings; DROP TABLE ratings"})
        print(r.is_error, r.content[0].text)

asyncio.run(main())

На игровой таблице ratings (1000 строк, SQLite) вышло: список инструментов ['describe_table'], rows = 1000, доля пропусков в rating — 0,18, а запрос с инъекцией вернул is_error=True и текст Error executing tool describe_table: table name must be a plain identifier. Попытка DROP TABLE через соединение с mode=ro падает с attempt to write a readonly database. Для интерактивной отладки в документации SDK есть uv run mcp dev server.py (инспектор; команда mcp ставится с extra mcp[cli]: uv run --with "mcp[cli]" mcp dev server.py).

Две вещи, о которых сервер не должен забывать. В stdio-режиме stdout занят протоколом: print в сервере сломает обмен, логи — в stderr. А описание инструмента (docstring) — это то, что читает модель: оно решает, когда её вызовут.

Цена в контексте

Каждый инструмент — это имя, описание и JSON-схема параметров. Двадцать серверов по десять инструментов — это тысячи токенов до первого вопроса. Claude Code по умолчанию откладывает определения MCP-инструментов (tool search): при старте загружаются только имена и инструкции серверов, остальное подтягивается по требованию; у серверов есть и верхний предел на размер описания. В Codex список ограничивают вручную: enabled_tools / disabled_tools. Правило одно: подключайте только то, чем пользуетесь, и держите описания короткими и конкретными.

Безопасность

  • Результат инструмента — недоверенный ввод. Текст из трекера, веб-страницы или письма может содержать «инструкции» для модели. Документация Claude Code прямо предупреждает: серверы, получающие внешний контент, открывают риск prompt injection. Подробности и «смертельную тройку» разберём в статье про безопасность.
  • Минимум прав. Отдельная учётная запись с read-only доступом вместо вашей основной; в примере выше — mode=ro, а не «модель же не будет писать».
  • Секреты — в окружении, не в .mcp.json и не в config.toml под git. Claude Code подставляет ${VAR}, Codex пробрасывает имена через env_vars и bearer_token_env_var.
  • Доверять серверу — значит запускать его код с вашими правами. Ставьте серверы известных поставщиков или пишите свои, читайте исходники, закрепляйте версии. Anthropic не проводит аудит чужих MCP-серверов.
  • Проектный .mcp.json из чужого репозитория в интерактивном режиме требует подтверждения, но в неинтерактивном claude -p серверы проекта подгружаются без вопроса.

Когда лучше CLI и скилл

Если у системы уже есть хороший консольный клиент (gh, psql, git, aws), часто проще дать агенту команду плюс скилл с правилами её применения: ничего не висит в контексте, права ограничивает обычный механизм разрешений, поведение воспроизводимо. MCP нужен, когда нужно: долгоживущее соединение или аутентификация, структурированные ответы, один сервер для многих клиентов, доступ туда, где нет CLI. См. скиллы.

Ловушки

  • Подключить десяток серверов «на всякий случай»: контекст и поверхность атаки растут, польза нет.
  • Дать серверу доступ на запись или боевые учётные данные, потому что «так проще».
  • Положить токен в .mcp.json или config.toml и закоммитить.
  • Слепо доверять тексту, вернувшемуся из инструмента: он мог написать кто угодно.
  • Писать print в stdio-сервере или копировать код под FastMCP на mcp 2.x.
  • Не ограничивать размер ответа: тысяча строк таблицы в контексте — это дорого и бесполезно.

Проверь себя

Сколько адаптеров нужно без MCP и сколько с ним?

N инструментов × M клиентов адаптеров без протокола; с MCP — N серверов и M клиентов, каждый реализует протокол один раз.

Чем различаются tools, resources и prompts?

Tools — функции, которые вызывает модель; resources — данные, подкладываемые в контекст; prompts — шаблоны запросов. Сервер может предоставлять любые из них.

Чем stdio отличается от Streamable HTTP и что выбрать для локального сервера над вашим файлом?

stdio — подпроцесс на вашей машине, общение через stdin/stdout, один клиент, без сети. HTTP — сетевой сервер для многих клиентов с авторизацией. Для локального файла — stdio.

Почему `mode=ro` лучше фразы «не пиши в базу» в описании инструмента?

Описание — просьба к модели, и её можно обойти инъекцией или ошибкой; mode=ro — ограничение на уровне системы, которое от решений модели не зависит.

Почему вывод MCP-инструмента нельзя считать безопасным и что с этим делать?

Он содержит данные из внешних источников, а модель может принять их за команды. Давать минимальные права, не соединять в одной сессии приватные данные, недоверенный контент и канал отправки наружу, проверять опасные действия вручную.
