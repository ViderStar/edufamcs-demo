Python для ML: что нужно на самом деле

10 мин АЛАртем Лебедевич 10 ноября 2026

Для работы ML-инженера нужна малая часть Python — зато та, которую вы используете ежедневно, и ошибки в ней стоят дорого: мутабельный аргумент по умолчанию, случайно изменённый общий массив, генератор, который можно прочитать один раз. Эта глава — минимум, который отличает «пишу скрипты» от «пишу код, который можно поддерживать», и типичные вопросы собеседований на роль ML-инженера.

Изменяемость и ссылки

Переменная в Python — имя, привязанное к объекту; присваивание копирует ссылку, а не данные. Изменяемые объекты (list, dict, set, ndarray, DataFrame) меняются на месте, неизменяемые (int, str, tuple, frozenset) — нет.

python
def bad(x, acc=[]):          # список создаётся ОДИН раз, при определении функции
    acc.append(x)
    return acc

print(bad(1), bad(2))        # [1, 2] [1, 2] — один и тот же список

def good(x, acc=None):
    acc = [] if acc is None else acc
    acc.append(x)
    return acc

print(good(1), good(2))      # [1] [2]

Тот же механизм даёт вторую классическую ошибку: [[0]*2]*2 создаёт два указателя на один внутренний список.

python
a = [[0] * 2] * 2;  a[0][0] = 1;  print(a)   # [[1, 0], [1, 0]]
b = [[0] * 2 for _ in range(2)];  b[0][0] = 1;  print(b)   # [[1, 0], [0, 0]]

Копии бывают поверхностные (x.copy(), x[:], list(x)) и глубокие (copy.deepcopy). Поверхностная копия [[1], [2]] создаёт новый внешний список, но вложенные списки остаются общими: s = x.copy(); s[0].append(9) меняет и x. В NumPy и pandas добавляется третий вариант — view (представление на те же данные, см. главу про NumPy).

Ловушка

Аргумент по умолчанию вычисляется при определении функции. def f(x, cache={}) хранит кэш между вызовами — иногда осознанно, чаще — как баг, который проявляется только при втором запуске.

Comprehensions и генераторы

python
squares = [i * i for i in range(10) if i % 2 == 0]       # список: хранится целиком
index = {w: i for i, w in enumerate(["a", "b", "c"])}    # словарь
g = (i * i for i in range(10**9))                         # генератор: значения по требованию
print(next(g), next(g))                                   # 0 1

Генератор считает значения лениво и занимает фиксированную память: sys.getsizeof списка из 1000 чисел — 8856 байт, генератора — 192 (число зависит от версии Python, порядок разницы — нет). Читать огромный файл или поток батчей надо генератором (yield). Но генератор одноразовый: второй проход по нему пуст, и это источник тихих багов («почему вторая эпоха не обучается?»).

Словари и множества

dict и set — хэш-таблицы: поиск, вставка и удаление в среднем O(1), ключи должны быть хэшируемыми (tuple — да, list — нет). Проверка x in list — O(n), x in set — O(1); если вы проверяете принадлежность в цикле, превратите список в множество:

python
seen = set(train_ids)                       # один раз
mask = [i not in seen for i in test_ids]    # O(len(test_ids)), а не O(n*m)

Словари сохраняют порядок вставки (гарантия языка с 3.7). Полезные из collections: Counter (частоты), defaultdict(list) (группировка без проверок ключа), deque (очередь с O(1) с обоих концов).

python
from collections import Counter
from itertools import batched, pairwise

print(Counter("abracadabra").most_common(2))   # [('a', 5), ('b', 2)]
print(list(pairwise([1, 2, 3, 4])))            # [(1, 2), (2, 3), (3, 4)]
print(list(batched(range(7), 3)))              # [(0, 1, 2), (3, 4, 5), (6,)]  — Python 3.12+

Функции, *args/**kwargs, dataclasses, типы

*args собирает позиционные аргументы в кортеж, **kwargs — именованные в словарь; при вызове те же звёздочки распаковывают. Типичное применение — проброс параметров: model = Model(**cfg).

python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class TrainConfig:
    lr: float = 1e-3
    layers: tuple[int, ...] = (64, 32)
    tags: list[str] = field(default_factory=list)   # изменяемое значение — только так

print(TrainConfig(lr=0.1))
# TrainConfig(lr=0.1, layers=(64, 32), tags=[])

@dataclass генерирует __init__, __repr__, __eq__; frozen=True запрещает присваивание полям — конфиг эксперимента не должен тихо меняться по ходу. Для изменяемых значений по умолчанию dataclass сам откажется принять tags: list = [] (ValueError), поэтому нужен default_factory. Аннотации типов (def f(x: np.ndarray, k: int = 10) -> list[int]) Python не проверяет при выполнении — их читают люди, IDE и статические проверщики (mypy, pyright). Для ML-кода хватает аннотаций на публичных функциях и dataclass'ов для конфигов.

pathlib, контекстные менеджеры, исключения, f-строки

python
from pathlib import Path
from contextlib import contextmanager
import time

root = Path("data") / "raw"                   # оператор / склеивает пути
files = sorted(root.glob("*.parquet"))
text = (root / "readme.txt").read_text(encoding="utf-8") if (root / "readme.txt").exists() else ""

@contextmanager
def timer(name: str):
    t = time.perf_counter()
    try:
        yield
    finally:                                   # выполнится даже при исключении
        print(f"{name}: {time.perf_counter() - t:.2f} s")

with timer("load"):
    pass

try:
    value = int("12x")
except ValueError as e:                        # ловите конкретное исключение, не голый except
    print(f"bad input: {e}")
print(f"{3.14159:.2f} {1234567:,} {0.5:.1%}")  # 3.14 1,234,567 50.0%

with гарантирует освобождение ресурса (файл, соединение, блокировка, torch.no_grad()). Path заменяет os.path.join и склейку строк, а с ним нет проблем с разделителями на Windows. Не ловите Exception молча: ошибка данных, проглоченная в обучающем цикле, превращается в «модель странно учится».

GIL и когда нужен multiprocessing

GIL (глобальная блокировка интерпретатора) в стандартной сборке CPython позволяет выполнять байт-код только одному потоку одновременно. Следствия: потоки не ускоряют чистый Python-код на CPU, зато ускоряют ввод-вывод (сеть, диск), потому что на ожидании блокировка отпускается. NumPy, PyTorch и pandas делают тяжёлую работу в C/C++ и на время вычислений GIL отпускают — поэтому векторизованный код быстр и (частично) многопоточен. Когда чистый Python-цикл упёрся в CPU, берут multiprocessing / concurrent.futures.ProcessPoolExecutor (отдельные процессы, данные сериализуются между ними) либо переписывают горячее место векторно. Free-threaded сборки (без GIL, PEP 703) появились в 3.13 как экспериментальные, с 3.14 официально поддерживаются (PEP 779), но это отдельный вариант интерпретатора (python3.14t), а не сборка по умолчанию; колёса под него есть не у всех ML-библиотек, поэтому на практике пока работают на обычном CPython; для собеседования достаточно понимать суть.

Профилирование

Сначала измерьте, потом оптимизируйте. В ноутбуке:

python
%timeit sum(i * i for i in range(10_000))        # время одной строки; %%timeit в первой строке ячейки — всей ячейки

Для скрипта — cProfile:

bash
uv run python -m cProfile -o prof.out train.py
uv run python -c "import pstats; pstats.Stats('prof.out').sort_stats('cumtime').print_stats(10)"

Смотрите на cumtime (время с вложенными вызовами) и ncalls. Типичный вывод: 90 % времени — один цикл по строкам DataFrame или apply; лечится векторизацией. Для памяти — tracemalloc и df.memory_usage(deep=True).

Ловушки

  • Изменяемый аргумент по умолчанию; [[0]]*n; a = b вместо копии, когда b потом мутируется.
  • Генератор, прочитанный дважды; zip по генератору и списку разной длины молча обрезает по короткому (zip(..., strict=True) — исключение).
  • is вместо == для сравнения значений (is проверяет тождество объектов, а не равенство).
  • Конкатенация строк или list + list в цикле (O(n^2) по общему размеру): собирайте в список и делайте "".join(...).
  • Мутация объекта внутри for x in lst: lst.remove(x).
  • Вопросы на собеседованиях: чем список отличается от кортежа и множества; что такое хэшируемость; почему 0.1 + 0.2 != 0.3; что делает yield; как работает декоратор; что такое GIL и зачем тогда NumPy-потоки; разница copy и deepcopy; сложность in для list и set; чем @staticmethod отличается от @classmethod; задача «найти дубликаты / топ-k частых / два числа с суммой s» за O(n) через dict/Counter.

Проверь себя

Что выведет `def f(x, a=[]): a.append(x); return a` при `f(1); print(f(2))` и как исправить?

[1, 2]: список создан один раз при определении. Исправление — a=None и a = [] if a is None else a внутри.

Почему `x in set` быстрее `x in list` и когда это не так?

Множество — хэш-таблица, поиск O(1) в среднем; список просматривается линейно, O(n). На очень коротких последовательностях (единицы элементов) разницы практически нет, а построение множества стоит O(n) — для разовой проверки оно не окупается.

Почему NumPy-код быстр, если в Python есть GIL?

Цикл выполняется в скомпилированном коде C поверх непрерывного блока памяти с типизированными элементами, а не в интерпретаторе по одному объекту; на время вычислений NumPy отпускает GIL.

Когда использовать потоки, а когда процессы?

Потоки — для ввода-вывода (скачивание, чтение файлов), процессы — для CPU-bound чистого Python-кода. Цена процессов — сериализация данных между ними и дублирование памяти.

Чем `copy.copy` отличается от `copy.deepcopy` на `[[1], [2]]`?

copy создаёт новый внешний список с теми же вложенными объектами, deepcopy рекурсивно копирует и вложенные; после s = x.copy(); s[0].append(9) исходный x тоже изменится ([[1, 9], [2]]), после deepcopy — нет.
